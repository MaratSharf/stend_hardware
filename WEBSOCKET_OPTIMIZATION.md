# Оптимизация WebSocket соединений

## Проблема
Частые GET-запросы к `/socket.io/?EIO=4&transport=polling` вызывали высокую нагрузку на сервер. Это происходило потому, что Socket.IO по умолчанию использует Long-Polling транспорт.

## Решение

### 1. Серверная часть (web/app.py)
- Добавлен `gevent` для асинхронной обработки WebSocket соединений
- Включена HTTP компрессия для уменьшения размера передаваемых данных
- Установлен `async_mode='gevent'` для высокой производительности
- Monkey-patching выполнен до всех остальных импортов

### 2. Клиентская часть (web/static/js/websocket.js)
- Изменена конфигурация Socket.IO клиента:
  - `transports: ['websocket']` - используем только WebSocket
  - `upgrade: false` - отключаем апгрейд транспорта
- Добавлена функция `tryFallbackPolling()` для fallback на polling если WebSocket недоступен
- Улучшена обработка ошибок подключения

### 3. Зависимости (requirements.txt)
Добавлены новые пакеты:
- `gevent>=21.0.0` - асинхронная библиотека
- `gevent-websocket>=0.10.1` - WebSocket поддержка для gevent

## Установка
```bash
pip install -r requirements.txt
```

## Результат
- Количество HTTP-запросов значительно уменьшено
- Используется одно постоянное WebSocket соединение вместо частых polling запросов
- При недоступности WebSocket автоматически используется fallback на polling
- Улучшена производительность и отзывчивость веб-интерфейса

## Проверка работы
После запуска сервера откройте консоль разработчика в браузере (F12):
- Должно быть сообщение `[WebSocket] Подключено`
- В сетевых запросах должно быть видно WebSocket соединение (статус 101 Switching Protocols)
- Частые GET-запросы к `/socket.io/...transport=polling` должны отсутствовать
