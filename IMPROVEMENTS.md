# Предложения по улучшению stend_hardware

**Дата:** 10 июля 2026

---

## Критичные

### 1. ~~Пароль в config.yaml открытым текстом~~ ✅ РЕШЕНО
Пароль хранился в репозитории в открытом виде. Перенесён в `.env` файл.

### 2. Нет тестов
Ни одного теста. Минимум: `verify_user`, `create_session`, state machine сценариев.

### 3. ~~Создание нового соединения БД на каждый запрос~~ ✅ РЕШЕНО
`get_connection()` открывает/закрывает psycopg2 на каждый вызов. Нужен connection pool (psycopg2.pool).

---

## Важные

### 4. ~~Дублирование кода сценариев~~ ✅ РЕШЕНО
Сценарии A, B, C имеют похожую логику (лампы, ошибка, сброс). Вынесено в общие методы `_trigger_measurement`, `_set_lamps`, `_reset_lamps`, `_handle_result_lamps`.

### 5. ~~_main loop глотает исключения~~ ✅ РЕШЕНО
`except Exception` в цикле `_run` логирует и продолжает. Добавлены кастомные исключения `CriticalError`, `HardwareError`, `DatabaseError` с порогами срабатывания.

### 6. ~~Нет graceful shutdown~~ ✅ РЕШЕНО
`Ctrl+C` может оставить конвейер включённым. Добавлен принудительный сброс выходов (`_reset_outputs(force=True)`) в `stop()` и обработчиках сигналов.

### 7. ~~WebSocket не reconnect~~ ✅ РЕШЕНО
При перезапуске сервера клиент не переподключается автоматически. Установлен `reconnectionAttempts: Infinity`, polling запускается как fallback при отключении.

---

## Удобства

### 8. ~~Нет healthcheck endpoint~~ ✅ РЕШЕНО
`/api/health` — uptime, статус БД, OWEN, камера. Реализован в `web/pages/health.py`.

### 9. Нет rate limiting на API
Открытый доступ к `/api/*` без ограничений.

### 10. Логи не ротируются по времени
Только по размеру (10 МБ). Нужна ротация по времени (ежедневно).

### 11. Нет backup/restore для БД
Экспорт в CSV/JSON по расписанию.

### 12. Конфиг не валидируется
Опечатка в config.yaml молча игнорируется. Нужна schema validation (pydantic/jsonschema).
